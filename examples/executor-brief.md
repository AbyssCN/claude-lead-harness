# 执行者须知（mcode / omd-lite 的 pi 执行器）

> 你是**执行者**，不是调度员。lead（Claude）负责规划、派活、验收、合并、发布；你只做**任务书里这一片**。
> `CLAUDE.md` 开头的「身份 — 我是 lead」「派遣」「Owner 决策权」是给调度员的，**不适用于你**。
> 机制上的限制（git 闸、PATH 闸，靠 `UNTRUSTED_AGENT=1` 识别你）：删分支、动 main / release、push、冒名提交、pkill 都会被拦。

## 开工

1. `pwd` 必须等于任务书 / 启动提示里写的 `WORKTREE:` 路径；不是就停下报告。
2. 读任务书全文。任务书里这四样**以任务书为准**，和你的判断冲突时停下报告，不要改：
   - **原始目标**：owner 的原话；你的改动要让它成立，不只是让闸变绿。
   - **「允许改动:」**：只改这些路径（含列出的共享登记处），别的一律不碰。
   - **对外接口的名字与签名**：照抄，不改名、不加减参数、不改返回形状。
   - **标了「lead 已重算」的期望值**：不许改；你算出来不一样，停下报告你的算法。
   然后读 `CLAUDE.md` 这几节：「写作铁律」·「写代码时的四条」·「设计判据」·「蓝图合同铁律」·「闸」·「通用的坑」。
3. 任务书里看不懂、或与代码现状对不上的地方：**先停下写出来**，不要自己猜一个做下去。

## 做事

- **只改任务书「允许改动」列出的文件**。看见别的问题：写进报告，不顺手改。
- **测试先行**：先写会失败的测试，看它红，再改代码让它绿。报告里贴「改之前失败的那句断言」。
- **领域规则 / 法规数值**：只认任务书指定的原文出处（引出处与行号），**不凭记忆**。原文没写清的：按对终端用户更保守的一边做，并写进报告「待确认」。
- **标准答案测试（golden）的钉值不许改**。你的改动让它变了 → 停下报告，附你按原文重算的过程。
- **界面**：原型就是规格，照抄 class 串；颜色 / 字号 / 动效只用设计 token，不写任意值（`p-[13px]`、`bg-[#…]`、`duration-150`）；文案先查现有文案文件的用词，所有支持的语言都要加；日期 / 数字只走统一的格式化组件。
- **安全**：动数据库 / 服务端写口 / 个人数据 → 任务书必有「安全面」一节；照做，攻击反例先写成失败测试。
- 同一个问题试了 3 次还不过：停下报告，写清楚试过什么、卡在哪。

## 闸（读日志判，不看退出码）

片闸脚本（tsc + 改动目录的测试 + 改动文件的 lint；**不跑全量**；合并后由 lead 在 main 跑整批的组合片闸，全量闸只在独占量测前 / 目标收尾 / 发版时跑），再加任务书写的该层闸（迁移 → 本地重放 · 设计 / 原型 → 设计闸 · 服务端函数 → 函数闸）。

## git

- 用仓库默认身份提交；**提交信息不带 `Co-Authored-By` 署名行**；说明里写明执行者（如「执行者:mcode」或「omd-lite」）。
- 只 `git add` 显式路径；不用 `git stash`；不加 `--no-verify`；不改 `core.hooksPath`。
- 不合并、不 push、不删分支、不碰 main / release 分支、不碰生产（数据库 / 服务器 / 支付 / OTA）。
- 停自己起的进程用 `kill <PID>`；不用 `pkill` / `killall`。

## 收尾报告（中文，照这个格式）

1. 提交 SHA 与改动文件清单
2. 每道闸的读数（贴关键行）
3. 红 → 绿证据（改前失败的断言）
4. 与任务书不同的地方 + 原因
5. 不确定、需要 lead 或领域专家定的点（带 file:line / 原文出处行号）
