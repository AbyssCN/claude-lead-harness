# /contract — 审议结晶成执行契约

审议(`/grill`)收敛后,把结论写成结构化 SDD 落盘——它是执行方(Opus 子 agent 或 `omd-lite run`)的执行契约,写给**没有对话上下文的执行器**,不是给人读的散文。

## 承接 /grill 的决策记录表

| # | 决策 | 定论 | 落点(/note · SDD 章节) | 证据 |
|---|------|------|-------------------------|------|

落点标「SDD 章节」的行 → 进「决策」与「契约」段;标 `/note` 的留台账。「待 owner / 待实测」项原样进「未决」,不写成结论。

## 落盘

路径:`docs/plan/YYYY-MM-DD-<slug>.md`(仓有自己的目录约定就照仓)。每段可被无上下文执行器独立消费:

```markdown
# <标题>
## 目标 (Destination)   一句话讲清做成什么样
## 决策 (Decisions)     D-1..D-N:每条已定型裁决 + 一句为什么 + 证据
## 八问 (Eight)         myapp CLAUDE.md 产品三问 + 设计三问 + 7 · 8 逐条答;内部工具 / 纯基础设施写「不适用:<理由>」(合并闸只认这一节在不在)
## 脏场景 (Dirty)       数据对不上 · 并发 · 部分失败 · 跨边界 · 生命周期末端 · 量级膨胀,每条写这份契约怎么扛;有「实验」节就写全四要素(单一变量 · 成败信号 · 基线 · 下一步收什么数据)
## 契约 (Contracts)     测试接缝(一行,承 /grill)+ 原始材料(一行)+ 判官(一行,工具命令)+ 不变量 + GWT 验收点 + 冻结的接口——执行方逐条判 pass/fail 的依据
## 分解 (Breakdown)     切片表 + 并行波形(写法见下)
## 非目标 (Non-goals)   明确不做什么
## 未决 (Open)          未裁的问题;待实测的标「待实测」
```

契约段第二、三行写**原始材料**(从什么没被消化过的材料起:PDF 行号 · 迁移文件 · 流水,不是别人的汇总)与**判官**(哪条工具命令说了算,模型的判词不算;承 `/grill` 铁律 8 的四问)。GWT 验收点越可证伪,验收越不含糊;一个模糊验收点 = 执行器和你各自解读的裂缝。契约段第一行写**测试接缝**(在哪个公共边界验,`/grill` 铁律 7 定的那条),GWT 都挂在接缝上,不挂内部实现。用词只用仓根 `GLOSSARY.md` 里的叫法;SDD 里出现词表没有的领域词 → 先补词表。

**非平凡接缝先「设计两次」(可选)**:新接口跨函数边界、形状一旦定下难改的,先 `/bestof arena` 出两个**结构不同**的类型 + 签名草图(调用方用法先写,类型从用法推),选 base 再把签名写死进契约段;点修补不算第二个候选。

## 分解段 —— 默认并行,串行必须给理由

- 只写**真实依赖边**,每条带理由:「B 依赖 A 因 <B 消费 A 的产物 X>」——且 **X 必须出现在 A 的写集里**。写不出被消费产物的边,删——那是顺序偏好,不是依赖。
- **接口依赖就地消解**:B 只需要 A 的类型/签名/schema 而非实装 → 把该接口**冻进本 SDD 契约段**,边删掉,两片并行。A 的实装必须符合它;偏离 = 回流改契约,不是恢复边。
- 切片表:`| 切片 | 写集 | 阻塞于(带理由) | verify |`。切片编号用裸数字(`1`、`2`…),波形与依赖靠它引用。「阻塞于」= 上面那条依赖边的落点,空 = 可立即开始;delegate 据它算可派的前沿,不再靠手排合并顺序。
- **写集两两不相交** = 可并行的判据。写集只放相对路径,不许留空或写「无」;要动的共享登记处(迁移号、注册表、文案键)也列进去。
- **verify 列是可跑命令**(如 `bun test src/x.test.ts`),不是验收点引用(G 点的家在契约段)。全量回归不进 verify 列,它属于整批合并后的验收。
- 新建文件的片,verify 要选**实装前必然红**的命令;改既有绿测试的片,换一条改前必红的(如 `rg -q '<实装后才出现的串>' <文件>`),否则这条 verify 判不出做没做。
- 收尾写并行波形,**独占一行**:`并行波形:{1,3,5} → {2} → {4}`。全串行须给整体理由,默认视为写错。
- 优先序写波形注释或 Open 段,不进依赖边。

## INV / GWT 的形状

- **仓里有契约闸就照它的格式另写一节 `## 不变量`**:写之前看仓里有没有契约检查(myapp:`scripts/check-contract-invariants.mjs`,G-N / G-O)。有 → 「契约」段之后加 `## 不变量`,按该脚本文件头的格式写(`### INV-<ID>` · 执行点 · 判定式 · 六类事件表 · 生成器,另要模型测试);契约不引入状态 / 权限 / 写入时只写一行 `不适用:<理由>`。落盘后跑一次该检查(myapp:`node scripts/check-contract-invariants.mjs <契约路径>`),红了先修再交。(18.10:F1 · F2 两份契约都在组合片闸上红在这里。)
- 不变量:`- **INV-1 短输出零回归**:…`(列表项 + 粗体 + `INV-`)。
- 验收点:`- **GWT-1** *Given* … *When* … *Then* …`;嵌在对应 INV 下当子项,或正文点名 `(INV-1)`。
- 别写 `- INV-1 …`(不加粗)或 `**G** … **W** … **T**` 简写——检查器认不出,会数成 0 条。
- **Then 写机器判得了的东西**(`.includes('…')` / 具体数字 / 文件路径);「合理」「符合预期」不算。

## 切片派给 omd-lite / MiniMax:每片展开成一份任务书

SDD 是总契约;派 MiniMax 时每片另写一份自含任务书,形状照 C-1b(`<lead-harness>/docs/plan/2026-10-10-lead-harness.md` §C-1b,范本 `~/repos/myapp/docs/plan/10.11/px-ui3-touch2.md`),开头链回本 SDD:

```markdown
# <片名> · <一句目标>(<执行方> 任务书)
**原始目标原文(<owner> MM.DD)**:「…」          逐字,不转述
证据:<SDD 路径 + 切片号;哪份测量说明这片该做>
执行者须知 `docs/process/executor-brief.md`。
**允许改动:** <空格分隔路径> = SDD 该片写集,含共享登记处
**阻塞于:** <切片号,或「无」> = SDD 切片表同列;被阻塞的片不派,等上游合并
## 借的方法(<slug>)  从被执行仓 `docs/methods/<slug>.yaml` **抄进来**(原始材料 · 照做 = instruments · 禁止 = anti_patterns · 判官 = 一条成功判据里的命令);碰钱与权限的片必填且不许写「无」,其余可选(方案稿 10.17 ambition-framework §3.3)
## 设计裁定(写死)    冻结的接口名与签名照抄 · 不变量 · 期望值标「已重算」 · **不做**清单
## 测试(先红后绿)    每条新断言后写「在 main 上红」;已有测试不改断言
## 成功判据            片闸绿 · 该层的闸绿 · `git diff <base> --stat` 只含允许改动文件
## 安全面              动数据库 / 服务端写口 / 个人数据才写
```

- **逐字 / 判据由写的人声明(18.10 owner 定,myapp)**:允许改动 · 对外签名两行,以及「设计裁定 / 测试 / 成功判据」节的每条列表项,句末恰带一个 `〔逐字〕`(字面本身就是要求)或 `〔判据〕`(行为等价即算做到);一句里两种都有就拆成两句,不许写混合。成功判据的文件范围写「只含允许改动的文件与测试文件」,与 piw 越界闸同口径。可以跑 `node scripts/dev/brief-decl.mjs <任务书>` 自查漏标，**只作自查，不进闸，判官也不读这两个标记**(19.10 owner 定:L1 第二批当场声明差 −1,前提不成立)。别把 〔逐字〕 标在测试的例子行上：实测会让 Sol 把等价写法判成 STOP。依据:事后让两家模型给旧任务书补标,归类只对上 68.5 %(`~/.local/share/owner-mods/bestof/myapp/brief-annot/frame.md`),意图读不回来。
- 限定边界,**不规定做法和第一步**(conductor lessons:规定第一步实测扣 0.06);能写就带 `--red-check "<新测试>"`(myapp `CLAUDE.md` 派遣节)。
- **成功判据用仓里现成的闸,写成「片闸绿(启动器在交付后跑 `scripts/dev/gate-slice.sh`;执行体不跑整道闸)」**,不要自造命令。执行体在沙箱里起整道闸会退 64(`docs/plan/2026-10-25-executor-no-full-gate.md`);它只跑自己新写 / 改的测试文件,一条命令一个文件。
- verify 要在 worktree 里真判得出:沙箱里的执行体**连不上数据库**(myapp `docs/process/omd-workhorse.md` §3 坑 3,omd leaf 实测);依赖 worktree 外环境的测试会被 `skipIf` 跳过、闸假绿(同文件 求解器 `.venv-solver` 那条)——这类片在判据里写明怎么补环境,或标「lead 另做」。
- 收片:闸绿 ≠ 交付。派只读子 agent `spec-reviewer`(`agents/spec-reviewer.md`,给任务书路径 + `git diff <base>...<head>`)报「缺 / 多 / 歪」三类,每条引任务书原句;bug 另走 `/code-review`,两轴分开报不合并排序(myapp:400 个 run 里 11 个零改动却报成功)。

## 纪律

- 只写已定型的决策;未决进 Open 段。
- **验收分两栏**:判据(必须能区分做完/没做)与护栏(防回归、本来就该绿)。把护栏当判据写,它在活还没干之前就已经满足,判不出东西。
- **钉性质,别钉行号。** 写「只改被本片必然打断的整串字面量」,不写「只能改第 58 行」——点名行号是替实装做了一个没查全的假设,会禁掉最小正确改动。爆炸半径约束的是碰哪些代码路径,不是行数。
- **写每条护栏前问:本片的改动会不会让这条断言改变?** 会 → 它不是护栏,是写集的一部分,连同「断言该改成什么」写进契约。**代理断言是重灾区**:测试断言的字面常常不是它想量的那件事;判据和护栏互相矛盾时执行体没有合法解。
- **每条验收出口前问两遍**:这条能不能验?**执行体有没有能力遵守它?**(它的沙箱跑不了的命令、它控制不了的引擎行为,都是做不到的条款。)
- 断言「不碰 X」要有对应的实测证据(跑生成器 / 闸看 diff 是否为空),不是 grep 一个名字——验了一条,别断言一片。
- 反引号里的路径、符号写之前上盘核对;编造的符号会被执行体照抄进命令,整条链首败。
- 无证据的决策行,先补证据或降级进 Open,不进 Contracts。
- 写完提示 owner:确认后交 Opus 子 agent 或 `omd-lite run` 执行。
- 看已有结晶 → `ls docs/plan/*.md` 按时间列出。
