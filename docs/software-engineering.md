# 软件工程纪律

只留「更强的模型也不会让它多余」的东西:模型外的结构,或者模型再强也不自带的方法。能写成检查的不写成规矩。

## 总原则

1. **可靠性来自模型之外。** 判词不算闸,退出码才算。
2. **不验证不提交。** 闸全绿才 commit。
3. **教训的终点是闸,不是记忆。** 踩过的坑写成一个在那次旧错上会红的检查。证不红的提案不收。
4. **闸绿不等于交付。** 一份实测里 400 个 run 有 18 个零改动、其中 11 个报了成功。合并前要读 diff 对任务书。
5. **每条纪律只许接或删。** 要么有程序守、有读数,要么删掉。没有读数的纪律会悄悄失效。

## 想清楚:契约

`/grill` 把方案问透,`/contract` 把结论写成契约。契约写给没有对话上下文的执行者看,必须有:

- **原话**:owner 的原话逐字保留,不转述。
- **不变量**:每条对应一个模型测试或检查。写不出检查的不变量等于没写。
- **脏场景**:数据对不上 · 并发 · 部分失败 · 跨边界 · 生命周期末端 · 量级膨胀,每条写怎么扛。
- **切片表**:每片写依赖和文件范围。

实装暴露契约错,就回流改契约,不静默绕过。

## 共同未知:实验四要素

现有信息定不了的事,不靠更长的推理,转成实验。动手前写全,缺一不算实验:

1. **单一变量。** 动了两个就分不清是谁的功劳。
2. **预先声明成败信号。** 事后再定判据等于没判据。
3. **对照基线。** 同一条件下量今天的值,不拿别处的旧数。
4. **下一步要收什么数据。** 好坏两种结果都写。

一个在任何干预下都不动的数,通常量的是尺子,不是对象。

## 切片与任务书

一片一份任务书,给执行者的全部上下文就是它。[`delegate`](../mods/delegate) 起片前机器检查,缺项拒派:

| 行 | 为什么 |
|---|---|
| 原始目标原文 | 让它成立,不只是让闸变绿 |
| 允许改动 | 只放路径;别处 import 这些文件的调用方也要列 |
| 对外签名 | 写死,执行者不许改名 |
| 已重算的期望值 | 总管亲手算过,执行者算得不一样就停下报告 |
| 成功判据 | 一条命令 |
| 安全面 | 碰敏感路径时必填,攻击反例先写成失败测试 |

规矩:每片文件范围互不重叠 · 修 bug 先写一个修前红的测试 · 依赖没合入不起片 · 任务书要先进基线分支。写法示例见 [`examples/executor-brief.md`](../examples/executor-brief.md)。

## 闸的阶梯

| 闸 | 什么时候 | 跑什么 |
|---|---|---|
| 片闸 | 执行者每轮 | 类型检查 · 改动目录的测试 · 改动文件的 lint · 泄漏扫描 |
| 层闸 | 碰到对应层 | 迁移重放 · 构建 · 设计检查 |
| 组合闸 | 一批合入后 | 这批改动合集跑片闸 |
| 全量闸 | 目标收尾 · 发版 | 全部 |

标准不许偷降:删测试、删断言、放松基线、无理由的抑制注释都要判红。

失败回灌规则:闸红把命令和输出尾 80 行喂回执行者;同一道闸连红 3 轮提前停;**供应商失败(过载、限流)不回灌**,换供应商或等窗口,回灌只会让模型去改无关的代码。

## 复核

- 执行者的报告不算证据,读 diff、跑检查才算。
- 跨模型发现不等于事实。用反例证伪:反例在今天的 main 上绿 → 驳回;红 → 修;证伪不了 → 附倾向升 owner。不延期,不擅断。
- 一次找全。不许一轮只挑一条。
- 被审的 SHA 写进判词。审完再改代码,判词作废(只改文档和测试除外)。
- 审查者不能看到彼此的判词,也不能看到写的人的自述。

轮数上限:方案 1 轮 · 每阶段 1 轮 · 发版 2 轮。只收可复现的 P0/P1 与契约违反,拒绝理论风险、风格意见和「加个监控」。

## 权限

- 写代码的执行者独占 worktree,prompt 带一行 `WORKTREE:`(`agent-guard` 强制)。
- 执行者不许删分支、动主干、push、冒名提交、pkill。靠 git 钩子和 PATH 闸,不靠提示词。
- 生产凭证和客户数据不进任务书(`briefDeny` 强制)。
- 只有四件事要 owner 同意:force push · 重置已推送历史 · 提交密钥 · 删带数据的表或切生产开关。其余总管自决,记在提交和交接里。

## 交接

状态放磁盘,不放对话,对话随时可以清。

- `GOAL.md`:原话 · 终点 · 验收命令 · 清单 · 决策账。[`relay`](../mods/relay) 按它续跑,到阈值写交接、`/clear`、新会话接着做。
- 回合末行 `RELAY: continue|done|owner|replan`。`done` 时 relay 自己跑验收命令,全过才停。
- `_NEXT.md` 只放现状和指针。
- 决策写「问题 · 推荐 · 备选」,一次最多 3 问,只问答案不同就会做出不同东西的。

## 写代码时

先写假设 · 最少代码,不写投机的灵活性 · 只碰非改不可的,不顺手改相邻代码 · 把任务翻译成会红转绿的判据。完整写法在 [`examples/CLAUDE.md`](../examples/CLAUDE.md)。
