# 活给谁做

**按活的性质分,不按「便宜的优先」一刀切。** 把跨层的活硬塞给便宜模型,在真实项目里白跑过两轮约 1.5 小时。

起片前先问四件事:单层吗?任务书写得死吗?有确定性的检查吗?文件少吗?四个都是 → 便宜执行模型。否则 → 强模型。

| 活 | 谁 | 启动方式 |
|---|---|---|
| 切好的片:单层、任务书写死、闸判得出 | 便宜执行模型 | `piw run` / `scripts/omdl-launch.sh` |
| 配音、出图、出视频 | 带多模态的执行模型 | `scripts/mcode.sh` |
| 只读复核、查代码、调研、截图核对、文档 | 中档模型子 agent | `Agent` 工具 `model: sonnet` |
| 钱、权限、迁移、同意流、契约 | 最强模型 | `model: opus`,独占 worktree |
| 规划、切片、终审、发布 | 总管 | 本会话 |

- **主管默认用最强模型的低 effort。** 排优先级和追真卡点最需要推理,这一层不要降模型。effort 由 `ticket` 启动参数给(`TICKET_CLAUDE_ARGS`),不写进 settings,否则子 agent 的终裁也一起降了。
- **钱与权限的终裁另起最强模型,不许降。**
- **模型 ID 只放一份配置**(`~/.config/piw/config.json`),其他地方只写角色名。写死过四处,换版本时配置改了不生效。

## 先算账再花钱

每个 token 和小时都是成本。起片前分类,写在任务书第一行:

| 类 | 是什么 | 默认去处 |
|---|---|---|
| V 版本功能 | 版本清单里的行 | 按排期做 |
| B 缺陷 | 现有功能不对 | 打分,够线才做 |
| G 守护 | 测试、检查、工具 | 只在挡住过真事故或正在白烧额度时做 |
| P 打磨 | 尺寸、文案、小样式 | 不单独做,并进同屏的 V 片 |

**缺陷打分 = 谁受影响 × 多严重 × 多常见**,每项 1 / 3 / 9。≥ 81 本版修 · 27–80 下版候选 · < 27 记一行不派。钱、权限、个人数据、法律一律按严重度 9 算。

## 复核的份数

| 级 | 范围 | 份数 |
|---|---|---|
| L1 | 不碰钱权限数据 | 0 |
| L2 | 一般 | 1 份异家族 |
| L3 | 钱 · 权限 · 迁移 · 个人数据 | 2 份异家族,最后总管终裁 |

**修复轮不再起模型。** 复核者的每条发现带一个会红的检查;修完检查转绿、片闸绿、改动只落在发现范围内,就算过。机器核不了的那一条才回原复核者,只审那一条。

撞额度、一个字判词都没有的复核不计份数。

## 算力

吃 CPU 的(测试、编译)送专门的机器,开发机保持轻;吃内存的留在开发机。`agent-guard` 的 heavy-route 能把命中名单的重命令改写成远程执行,配置项 `heavyRouteRepos` 默认只含示例仓名,你的仓不在名单里就不改写。它依赖的 `remote-run.sh` 还没进本仓,见 [ROADMAP](../ROADMAP.md)。
