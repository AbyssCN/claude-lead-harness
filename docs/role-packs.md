# 角色包(设计)

> 这是设计,还没有实现。结构示范见 [`examples/roles/frontend`](../examples/roles/frontend)。

会话不长期活着:一单一个。积累的是角色,不是会话。

建一个单独的 agent 仓(你自己的私有仓),每个角色一个文件夹,放身份、技能和规则。派活时从仓里调用角色,技能就不用每个项目各放一份。项目特有的规则留在项目仓,角色包只放跨仓通用的。

```
agents/
  frontend/
    ROLE.md     身份 · 接什么活 · 交付物 · 判据
    rules/      正式层:过了检查才进,角色启动时读
    skills/     角色专用技能
    inbox/      收集箱:什么都收,只有蒸馏程序读
  backend/  money/  release/ …
```

## 怎么越用越好

```
会话 checkpoint ─┐
retro 提案 ──────┼→ 收集箱 → 蒸馏程序 → 晋升检查 → 正式层 → 下一个会话启动时读
复核发现 ────────┘
```

收得宽,晋升严。晋升检查只用确定性机制:

1. 出处必填,追得到 run。
2. 扫描密钥与客户数据。
3. 人定的不会被覆盖。
4. 作废不删,留痕。
5. 召回出来的内容不算新证据,否则一条记忆能自己证明自己。
6. 同类至少出现 2 次才晋升。
7. 互相矛盾的转给人看,不自动裁。

不用向量库、不做衰减分数。两者都试过,都比文件夹和检查更难判断对错。

## 审批

能写成检查的自动放行 · 要判断的成批给总管 · 只有改角色身份才问 owner。

## 试点

顺序:先做卡死看护程序,再做一个前端角色包。试点前写死判据:同类界面错误的重犯次数。启用前量一次基线,启用后每周量一次。数不降就删掉这层。

## 卡死看护(程序,不是会话)

- 主管在等(复核、run、交接)时自动保温,最多 2 小时。
- 没在等就自动交接再关。
- 总管工作时段常保温。
- 人亲手用的会话不动。
